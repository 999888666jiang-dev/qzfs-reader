> 本文件只写「继承了什么、偏离了什么、本项目补充了什么」；与基线冲突时以本文件为准，并在下方列出理由。
> 状态：随架构设计一并通过，待用户确认后生效（2026-11-21）。

## 1. 从基线继承、原样执行

1. **文档先行**：需求、用户故事、设计、任务、验证先落成文件，再写代码；一个聊天只服务一个项目。
2. **spec 是契约**：只写规则与验收，不写伪代码、逐行实现、函数签名和常识。规则编号 `R-xx`，每条至少配一个可执行验收示例；不确定的单列「待确认」。
3. **编号贯通**：PRD → 用户故事 → spec → 数据/接口契约 → 任务表「需求编号」→ 测试 → `verification.md`。规则变化必须同步五处，不允许「只改代码」。
4. **节奏**：需求 → 原型 → 设计 → 编码 → 测试 → 运行；一次只推进一个可独立验收的小步，上一步未验收不抛下一步。
5. **验收**：正常流程、错误输入、边界值、持久化四类都要覆盖；接口/页面之外还要看本地存储里留下的数据，尤其是「失败后原数据是否还在」。
6. **README 四段**：安装、运行、测试、访问地址；缺一段不算交付完成。
7. **环境事实**：本机 Python 3.12.7、Node 24.16.0、npm 11.13.0、git 2.54.0、gh 2.97.0；**没有 uv**。新项目用系统 Python 自建环境，不写 uv 命令。
8. **风险纪律**：不过度乐观；改动前评估失败路径；C 盘与系统目录改动按 `~/.dsh/AGENTS.md` 执行。

## 2. 明确偏离（只允许以下四项，记为 X-01～X-04）

| 编号 | 基线写法 | 本项目 | 理由 | 影响 |
| --- | --- | --- | --- | --- |
| X-01 | 前端原生 HTML/CSS/JS，单文件内联，无构建、无框架、无 npm 依赖 | React + Vite + JSX，原生 CSS，构建产物静态托管 | 四份动效设计稿是 React + WebGL/GSAP 组件；手写等价实现约 2000 行且保真度不可控 | 需要 Node 构建与 GitHub Actions；前端代码不再是单文件 |
| X-02 | 后端 Python 3.12 + FastAPI，SQLite，`{code,message,data}` JSON 接口 | 无后端、无数据库；构建期把 TXT 生成为静态 JSON | 阅读站只读，GitHub Pages 无服务端；静态 JSON 可缓存、可离线 | 进度/书签只能存本机，不能跨设备自动同步 |
| X-03 | 页面由后端同源提供，前端请求 `/api/...` | 纯静态 SPA，hash 路由，资源相对路径 | 静态托管没有路由重写；hash 路由避免 404 hack，深链可刷新 | URL 带 `#`；分享链接形如 `.../#/read/c0001` |
| X-04 | 本机 demo 为默认交付，只监听 127.0.0.1 | 公网 GitHub Pages，手机可访问 | 用户明确要求「随时随地打开」 | 需处理子路径、缓存、PWA、版权与国内访问风险 |

除 X-01～X-04 外，其余基线继续有效。任何新的偏离（换 UI 库、加后端、加统计、换数据格式）必须先写 decision 记录并取得用户同意。

## 3. 本项目补充约定

### 3.1 目录与命名

- 文档正文全中文；文件名沿用项目既有命名（`requirements.md`、`architecture.md`、`specs/spec-v1.md` 等），引用用相对链接，不另造别名。
- `public/data/` 是生成产物，不手改；改数据只能改 `tools/` 或 `tools/overrides.json` 后重跑。
- 章节 ID 固定为 `c` + 四位零填充章节号：`c0001` … `c3233`；**编号一旦发布不再变**，避免书签/进度失效。
- 代码变量 lowerCamelCase；React 组件 PascalCase；CSS 变量 kebab-case；数据字段 lowerCamelCase。
- 页面文案用中文全角标点；文案中的章节号用「第 N 章」。

### 3.2 数据与规则

- 原文缺失的章节必须保留占位条目（`missing: true`），不得删除、不得改号、不得补写。
- 清洗只删站点广告与格式噪音，不改写正文；正文中的 `⚹`（U+26B9）是源文件脱敏占位，保留并在「关于」页说明。
- 同一章节存在多版本时，按 `docs/data-design.md` 的选版规则取一份；人工覆盖写在 `tools/overrides.json`，可追溯。
- 所有统计数字（章节数、缺失数、字数）以构建脚本输出为准；文档中的 2026-11-21 体检数字只作基线。

### 3.3 前端与动效

- 不引入任何第三方运行时请求：字体、图标、GSAP、图片全部本地打包；禁止 CDN。
- 动效四件套必须有：开关、`prefers-reduced-motion` 自动降级、WebGL2 能力检测、失败兜底静态图/静态标题。
- 阅读页默认不加载 GSAP 与 WebGL 组件（按路由懒加载），首章可读不依赖动效。
- 主题必须在 React 挂载前由 `index.html` 内联脚本应用，避免闪白；所有主题用 CSS 变量，不写死颜色。
- 所有用户可见错误都要有中文文案与恢复路径（重试、返回目录、重置设置），不允许白屏。

### 3.4 持久化

- `localStorage` 三个键：`qfs.settings.v1`、`qfs.progress.v1`、`qfs.bookmarks.v1`；每个值带 `version`。
- 读取必须 `try/catch` + 结构校验；损坏时回退默认值并 toast 提示，不阻塞阅读。
- 写入节流：滚动位置 ≥500ms 一次；页面隐藏/`pagehide` 时补写一次。
- 提供导出/导入 JSON，作为跨设备迁移的唯一正式手段（v1 不做云同步）。

### 3.5 测试与验证

- 语料管线用 `unittest`（标准库），不依赖 pytest；用合成小样本测规则，再用真实原文跑一次体检输出。
- 前端单元测试覆盖：存储 schema 与损坏回退、主题/字号应用、进度恢复、章节边界、缺失章节、搜索过滤。
- E2E 至少覆盖：首页 → 第 1 章 → 改字号/主题 → 刷新读回 → 下一章 → 目录跳转 → 书签 → 深链刷新 → 缺失章节提示 → 移动端 390×844 无横向滚动。
- 验证记录写实际命令、通过数量、浏览器版本、未实现项；不写「应该通过」。
