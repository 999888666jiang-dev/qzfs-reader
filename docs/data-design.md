# 语料与数据设计

> 版本：v1（2026-11-21）
> 本文是 `tools/build_corpus.py` 的契约：输入、规则、输出、校验、人工覆盖。
> 结论先行：原文是**多轮抓取拼接稿**，不能按标题直接切分；必须走「解析 → 清洗 → 选版 → 排序 → 补占位 → 校验 → 报告」。

## 3. 总体策略

1. **不改原文**：只删站点噪音、统一空白；不补字、不改写、不续写、不合并章节。
2. **一章一号**：`n` 固定 1–3,233，章号即章节 id 的依据；缺章保留空位。
3. **多版本选一**：按「干净优先、完整次之、后轮优先」评分；任何人工改动写进 `overrides.json`。
4. **可追溯**：每个正文文件带来源行号；质量报告记录每次选择与清洗数量。
5. **可重建**：同一输入 + 同一工具版本 = 同一输出（除 `builtAt`）；不使用随机数。
6. **原文不进 git**：生成物进 git；原文 SHA-256 写进 `meta.json`，保证可核对。

## 4. 构建管线

```text
读取字节 → 解码（utf-8-sig）→ 统一换行 → 逐行扫描
  ↓
候选标题（编号、标题、行号、缩进）
  ↓
剔除伪标题 / 广告标题 / 空壳
  ↓
正文切片（标题行到下一个候选标题行）
  ↓
清洗正文与标题（广告、BOM、空白、页码后缀）
  ↓
按章号分组 → 选版评分 → 人工覆盖 → 冲突标记
  ↓
1–3233 排序 → 缺失占位 → 标题兜底
  ↓
输出 meta.json / catalog.json / chapters/*.json / quality-report.json
  ↓
校验（结构、数量、广告残留、路径、编码）
```

## 5. 标题解析规则

候选行必须满足：

- 行首可有 0–4 个空白/全角空格（保留缩进信息），匹配 `^第(\d+)章`；编号 1–9,999。
- 去掉编号后的分隔符 `空格`、`　`、`:`、`：`，余下为标题；标题长度 ≤ 60 字符。
- 标题为空的候选保留（后续兜底），但评分加罚。
- 以下判为伪标题，不切片：
  - 行首缩进 ≥2 个全角空格，且该编号在当前序列中已有正常标题（行内重复标题）；
  - 标题或整行包含站点广告特征（见 §6）；
  - 行尾为 `。`、`，`、`、`、`；` 等叙述标点且长度 > 40（正文句子误匹配）；`！`、`？` 不在此列（章节标题常用）。
- 两轮抓取产生的重复标题都保留为候选，交给选版。

## 6. 清洗规则

### 6.1 全局

- 删除 U+FEFF（BOM）、U+200B–U+200D、U+2060、U+00AD。
- `\r\n`/`\r` → `\n`；连续 3 个以上空行压成 1 个空行。
- 段首全角空格与 ASCII 空格去掉；段尾空白去掉；段内多余空格压成 1 个（标题中的 NBSP 转普通空格）。
- 不删除 `⚹`、不替换 `⚹`、不猜测原字。

### 6.2 行级广告（整行删除）

以下正则命中且整行长度 < 200 时删除（保留作者正常括号注）：

| 正则（示例） | 说明 |
| --- | --- |
| `^如您已阅读到此章节` | 站点引导 |
| `^.*(笔趣阁\|小-说-网\|无⚹错).*$` | 站点名/手打标记 |
| `^.*(请记住\|记住本站\|收藏本站).{0,40}(网址\|域名\|www\.).*$` | 站点记忆 |
| `^.*百度(直接)?搜索.*$` | 搜索引导 |
| `^.*最新章节(已)?上传.*$` | 更新提示 |
| `^.*(https?://\|www\.)\S+.*$` | 裸 URL |
| `^（第\d+/\d+页）$` | 页码 |

### 6.3 行内后缀（截断）

- 站点标记：`请用小写字母输入网址`、`记住手机版网址`、`顶点…更新最快`、`书客居`、`蚂蚁阅读网`、`readChapter`、`加入书签`、`章节错误`、`一章节已更新`、`https: 数字` 等，从标记处截断或删除标记本身。
- `最新章节已上传；?`、`（第\d+/\d+页）`、`是由「…」…会员手打…`、`请记住…网址…` 出现在段尾时截断。
- 纯推广括号（求月票/推荐票/订阅/收藏/打赏/加更/断更/上架/公众号/QQ群/手机版/阅读器/正版/盗版）整段删除；`【…】` 形式的同类推广同样删除。
- 整段作者推广（含 `求票`、`月票`、`订阅`、`打赏`、`起点/创世/中文网`、`公众号`、`更新时间`、`每天…章更新` 等）在长度 <600 字时整段删除；不删除剧情中的「记住」「更新」「收藏」等普通词。
- 标题中的 `（今日中午11点新书发布！）` 这类更新公告：v1 规则是删除「括号内包含『新书/发布/更新/月票/推荐票』且长度 > 8」的尾部括号；其余括号（剧情说明）保留。人工可覆盖。

### 6.4 保留项

- 作者括号注（求票、请假、更新说明）默认保留；如影响阅读，后续可加「净化模式」，v1 不做。
- `⚹` 原样保留；关于页说明「源文件脱敏占位」。
- 章节标题中的剧情括号（上/下/中）保留。

## 7. 选版规则

对同一章号 `n` 的所有候选计算分数（越低越好）：

| 项 | 分值 | 说明 |
| --- | --- | --- |
| 站点广告残留 | +1,000 / 处 | 清洗后仍命中广告正则 |
| `⚹` 数量 | +20 / 处 | 后轮通常更少 |
| 标题为空 | +200 | 有标题优先 |
| 标题含广告/公告 | +150 | 清洗后仍异常 |
| 正文过短 | +300（<500 字）、+150（<1,000 字） | 防残段 |
| 长度偏离中位数 | `\|len - median\| / median × 120` | 防超短/超长拼接 |
| 后轮版本 | −5 | 同等条件取更靠后的抓取 |
| 人工指定 | 直接胜出 | `overrides.json` |

规则：

1. 先清洗再评分；评分只用清洗后的正文。
2. 取最低分；若前两名分差 <10 且标题不同，标 `needsManual`，仍取较低分者作为临时结果。
3. 若两组正文相似度 <0.9 且标题不同，视为**疑似错号**，标 `needsManual`，不改号、不合并，报告里单列。
4. 同号候选正文完全相同（归一化后）时，取行号更晚者，`srcLine` 记录来源。
5. 选版结果写入 `quality-report.selection`，含每组候选数、选中行号、分数、是否人工。
6. 人工覆盖优先于自动结果；覆盖必须填 `reason`。
7. 清洗后正文 <50 字视为无正文；若全组都 <50，生成缺失占位，不输出空章（避免「有章无文」）。

## 8. 缺失章与补章

### 8.1 占位

- 1–3,233 中无可用候选的章号生成占位：`{ n, title: "（原文缺失）", missing: true, paras: [] }`。
- `catalog` 状态位 1；目录显示「缺」；直接打开显示提示卡；不计入字数。
- 缺失章清单写入 `meta.missing` 与 `quality-report.missing`。

### 8.2 补章

两种方式，任选其一：

1. **补丁文件**：把补章文本放 `全法原本/supplement/*.txt`，格式为 `第2893章 标题` + 正文；构建脚本以最高优先级合并（只补缺失，不覆盖已有），报告标 `supplement`。
2. **整本替换**：用更完整的文本替换原文件，更新 `meta.source.sha256`，重跑构建；选版规则不变，人工覆盖按章号继续生效。

验收：补章后缺失数下降，`validate_corpus.py` 通过，正文无广告；不得为了凑数复制相邻章。

### 8.3 已确认缺失组（基线）

| 区段 | 缺失数 | 说明 |
| --- | --- | --- |
| 2,893–2,992 | 100 | 连续大洞，2,892 后直接 2,993 |
| 957–966 | 9 | 964 仅第一轮有，其余缺 |
| 1,863–1,866 | 4 | 连续 |
| 其余 | 19 | 分散（如 459、677、695、744、1,151、1,313…） |

## 9. 人工覆盖

`tools/overrides.json`（入库，人工维护）：

```json
{
  "version": 1,
  "selection": {
    "494": { "line": 25778, "reason": "标题冲突；取早版《火卷上海（上）》" }
  },
  "titles": {
    "3227": "邪庙女主人"
  },
  "dropLines": [156939, 157013]
}
```

- `selection.<n>.line`：指定候选行号（1-based），必须存在于该章候选；构建时优先使用并记录。
- `titles.<n>`：覆盖展示标题（不改正文）。
- `dropLines`：明确剔除的伪标题/广告行号（1-based），用于处理评分无法判断的边界。
- 覆盖失效（行号不存在/章号无候选）时构建失败并给出明确错误，不静默忽略。

### 10.2 `public/data/catalog.json`

```json
{
  "schema": 1,
  "volumes": [{ "id": "v01", "label": "第 1 卷", "from": 1, "to": 100 }],
```

### 10.5 体积预算

- 章节 JSON：约 20–22 MB（7.10M 字符，UTF-8）；gzip 后约 9–12 MB（按单文件响应压缩估算）。
- 单章：平均约 6.5 KB，最大 <25 KB。
- catalog：约 150 KB，gzip 后约 45 KB。
- `public/data/` 下共 3,235 个文件（3,233 章节 + `meta.json` + `catalog.json`）；质量报告另存 `reports/`。

## 11. 校验规则（`validate_corpus.py` 必须全部通过）

1. `catalog.chapters.length === 3233`；`n` 从 1 到 3233 连续且唯一。
2. `available + missing === 3233`；缺失清单与状态位一致。
3. 每个 `chapters/cNNNN.json` 存在、可解析、`n` 与文件名一致。
4. 正常章 `paras.length > 0` 且总字数 > 0（<100 字记 warning 并列入报告，不阻断）；缺失章 `missing === true` 且 `paras.length === 0`。
5. 正文与标题不命中 §6.2/§6.3 的广告规则；不含 U+FEFF、U+200B–U+200D。
6. 不含绝对路径、盘符、`http://`/`https://`（正文中的剧情 URL 除外，需报告白名单）。
7. JSON 均为 UTF-8 无 BOM、LF 换行、`schema` 版本正确。
8. 总字数与 `meta.chars` 误差 ≤1%。
9. `meta.source.sha256` 与当前输入文件一致（重建时校验）。
10. 若存在 `supplement/`，补章数量与报告一致，且不覆盖已有正常章。

失败时脚本以非零退出码结束，打印「第几条规则 + 具体文件 + 期望/实际」，不继续部署。

## 12. 构建命令

```powershell
# 1. 生成（默认读取 全法原本/《全职法师》作者：乱.txt）
python tools/build_corpus.py --input "全法原本/《全职法师》作者：乱.txt" --out public/data --report reports/quality-report.json

# 2. 校验
python tools/validate_corpus.py --data public/data

# 3. 管线单测
python -m unittest discover -s tools/tests -v

# 4. CI 只读校验（Node，不重建）
node tools/check_data.mjs
```

要求：

- 只用 Python 3.12 标准库；不联网；不向 C 盘项目目录/系统目录写文件（系统临时目录可用，构建后清理）；不修改原文。
- 输出目录先写临时目录，全部成功后原子替换，避免半成品。
- 同一输入重复构建，除 `builtAt` 外输出一致（`--deterministic` 可固定时间戳）。
- 报告与 `public/data` 同时产出；`reports/` 进 git 便于回溯。

## 14. 风险

- **补章不可自造**：缺失章只能用真实文本补；没有来源就保持占位，这是产品诚实性的一部分。
- **错号可能残留**：55 组原始冲突里可能有「两个不同章共用一个号」；清洗后仍有 38 组、33 组待人工复核。上线前必须抽查这 55 组。
- **`⚹` 影响可读性**：无法可靠还原；保留并在关于页说明，避免被误认为乱码。
- **版权**：生成物含全文并进入公开仓库；是否公开由用户决定，页面必须 `noindex`。
- **文本更新会改变选版**：换源后必须重跑报告并复核 55 组冲突与短章，不能只看总数。
