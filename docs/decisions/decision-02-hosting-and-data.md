# ADR-02：托管、路由与数据形态

- 状态：提议（待用户确认）
- 日期：2026-11-21
- 相关：`docs/architecture.md` §3、`docs/deployment.md`、`docs/data-design.md`

## 背景

站点要放在 GitHub Pages，手机随时打开；内容是 3,233 章、约 7.1M 字；没有后端；需要深链、刷新、离线与可重建数据。需要同时决定四件事：路由、数据切分、仓库内容、托管。

## 决策 1：hash 路由

**选择**：`#/read/c0001` 形式的 hash 路由，自研约 60 行。

**理由**：

- GitHub Pages 是静态文件服务，没有 SPA 重写；`#` 之后不参与请求，刷新与分享天然可用，不需要 `404.html` 兜底。
- 不引入 React Router，少一个依赖与版本面。
- PWA `scope` 与子路径配合简单。

**代价**：

- URL 带 `#`，观感不如 `/read/1`；部分聊天软件会截断 `#` 后内容（分享时需完整复制）。
- 无法做按路径的服务端统计（本项目也不需要）。

**不选**：history 路由 + `404.html` 重定向；对单站可用，但多一层脚本重定向，离线时更脆弱。

## 决策 2：数据按章切分

**选择**：`data/catalog.json` + `data/chapters/cNNNN.json`，构建期生成。

**理由**：

- 单章平均约 6.5 KB，按需加载；首屏只取 catalog（约 45 KB gzip）。
- 文件即缓存单元；SW 可按访问缓存，离线已读章。
- 目录与正文解耦；缺失章有独立占位文件。
- 静态托管零配置；GitHub Pages 对静态 JSON 友好。

**代价**：

- 3,233 个文件；首次批量抓取有请求开销（v1 不预取全书）。
- 无法服务端全文搜索（v1 只搜标题/编号；v1.1 再评估索引）。

**不选**：

- 单个 7 MB JSON：首屏/解析不可接受。
- SQLite WASM：需要额外 WASM 与初始化，收益低。
- 后端 API：违背静态托管与零成本目标。

## 决策 3：原文不进 git

**选择**：`全法原本/` 加入 `.gitignore`；仓库提交生成后的 `public/data/`、`tools/`、`reports/`。

**理由**：

- 33 MB 原文 + 20 MB 生成物会让仓库翻倍；CI 不需要原文。
- 生成物是部署所需；原文留在本机，`meta.source.sha256` 保证可核对。
- 避免仓库 clone 体积过大与版权暴露面扩大（虽然生成物本身也含全文）。

**代价**：

- 换机器/久后重建需要重新拿到原文；文档记录路径、大小、SHA。
- 若要「CI 一键重建」，需要把原文放到 GitHub Release（可选，v1.1 再评估）。

**不选**：Git LFS（增加使用门槛，Pages 不读 LFS）、把原文压缩后提交（仍 10 MB+ 且无必要）。

## 决策 4：GitHub Pages + Actions

**选择**：`main` push → Actions 构建 → `actions/deploy-pages` 发布 `dist/`；`base: './'`。

**理由**：

- 用户明确指定 GitHub；免费、HTTPS、可绑域名。
- 构建只在 CI，手机端只拿静态文件。
- 可回滚：重新部署上一个成功提交。

**代价**：

- 国内访问可能慢/间歇不可达；需实测，备选 Cloudflare Pages 同 `dist/`。
- 公开仓库 = 全文公开；私有仓库的 Pages 需要付费。
- 依赖 GitHub 的 Actions 配额（免费额度足够个人使用）。

## 决策 5：PWA 只缓存访问过的章节

**选择**：预缓存应用壳；data 请求 `NetworkFirst`，上限 80 章；全书缓存列为 v1.1。

**理由**：

- 全书约 20 MB，自动缓存会耗流量、占空间，且用户未必需要。
- 访问过的章节离线可读已满足「地铁继续读」。
- 更新用 `prompt`，避免读到旧章节。

## 综合后果

- 站点是「静态 SPA + 预构建数据」；无服务端、无账号、无云同步。
- 跨设备迁移只能导出/导入 JSON；这是 v1 的明确限制。
- 数据与代码同仓库、同版本；回滚时一起回滚。
- 页面必须 `noindex`；仓库可见性由用户决定。

## 何时重审

- 用户要求跨设备自动同步 → 需要后端或第三方存储，超出静态架构。
- 国内访问长期不可用 → 换 Cloudflare Pages/Vercel，只改托管，不改代码。
- 全文搜索成为刚需 → 先评估预构建索引体积（可能 10 MB+），再决定是否 v1.1。
- 仓库需要公开可重建 → 把原文放 Release 附件并在 CI 下载。
